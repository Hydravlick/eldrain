# Eldraine Crash Test

Use for adversarial review of an explicit mechanic, feature, incentive or state/interface contract. Input: intended decision, costs/rewards, repetition, limits and owners. Read [canon-ownership](../../policies/canon-ownership.md). State missing contracts rather than inventing intended behavior.

Build reproducible abuse chains: preconditions -> actions/event ordering -> result -> repeatability -> harm. Test applicable combat/resource bypass, risk-free profit, laundering/transfer, progression traps, sacrifice/griefing, party stacking and optimal boredom. Follow broad adoption, meta knowledge and capital into second-order population/economy effects.

For multi-step processes check simultaneous triggers, cancellation after payment, changed/lost targets, conflicting reservations, full capacity, unavailable POIs/Pawns, save/load/reconnect, offline catch-up and lifecycle transitions. Select applicable cases. Separate undefined resolution from demonstrated exploit.

Strength alone is not failure: account for counterplay, risk, time, niche and victim information. Separate owner evidence, inference and test assumptions. For loadouts read [gear-progression](../../references/gear-progression.md); for uncertain causality read [design-research](../../policies/design-research.md). Use Balance Modeler when numbers can change the verdict.

Lead with actionable findings: exact owner, reproduction chain, consequence, confidence and current counterplay. Include false positives and candidate repairs with costs where useful. Implement requested fixes under [editing](../../policies/editing.md) and [editorial-quality](../../policies/editorial-quality.md), without demanding a systemic redesign for every finding.
