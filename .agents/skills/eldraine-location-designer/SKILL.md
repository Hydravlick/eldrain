# Eldraine Location Designer

## Principle

Make each location a readable sequence of spatial decisions using a bounded production method.

## Current Sources

Read `00_Index.md`, the active location or sector owner, the active generation owner, and direct lore dependencies only when they define the location’s rule.

## Workflow

1. State the spatial promise and player decision.
2. Define the manual frame, procedural kernel, route grammar, landmarks, and connectivity invariants.
3. For every phase or tier, specify perception, interpretation, route delta, commitment, feedback, failure, and production method.
4. Classify implementation as state, bounded variant, set-piece, or simulation and choose the smallest method that preserves the decision.

## Output

Return `REALIZABLE`, `PROTOTYPE_REQUIRED`, or `OVERBUILT`; then provide the spatial arc, support and tensions, topology, phase table, success/retreat/failure paths, production map, prototype observations, and owners to update.

## Stop

If a route, extraction, or owner is unspecified, return `MISSING_OWNER`. If a shared decision spans owners, return `BLOCKED: ARCHITECTURE_DECISION_REQUIRED` with exact paths and one question. Recommend a specialist only when explicitly selected.
