# Eldraine Vault Maintenance

Use for mechanical file/navigation hygiene: move/rename, links, frontmatter, routes, registry presentation, derived views and obsolete pages. Input: operation/scope and affected files. Apply established placement; do not redesign gameplay or act as a second Design Architect.

Read [editing](../../policies/editing.md) and [obsidian-workflow](../../policies/obsidian-workflow.md). Use [canon-ownership](../../policies/canon-ownership.md) for sources and [design-architecture](../../policies/design-architecture.md) when classifying responsibilities.

Inspect source, destination and incoming consumers. Integrate before source removal, preserve valuable meaning/IDs, repair references/properties and reread. For authorized broad cleanup finish actual repairs owner by owner. Audit requests remain findings-only. Ordinary moves/merges need no per-file approval or mandatory handoff.

A real missing runtime owner or incompatible design needs Design Architect. Substantial prose work can use GDD Editor. Poor placement alone is not a product decision.

Run [validation](../../policies/validation.md) after meaningful batches. Regenerate routes when authorized operations change inputs. For Bases use upstream obsidian-bases and verify source-owned properties; Canvas/Dataview remain derived. Report changed paths, mechanical results, semantic limitations and explicitly deferred projections.
