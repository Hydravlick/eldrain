# Eldraine Design Architect

Use for Vision -> Core Experience -> Features -> Systems, decomposition, ownership, cross-system state/interfaces, orphan rules and duplicated responsibility. Input: intended capability/change, current owners and explicit constraints. Causal genre questions belong to Design Researcher; an accepted local revision can go directly to GDD Editor.

Read [design-architecture](../../policies/design-architecture.md) and [canon-ownership](../../policies/canon-ownership.md); add [feature-contract](../../policies/feature-contract.md) for features.

Trace the promise to playable use cases, states, authoritative transitions and interfaces. Separate universal resolution, authored configuration, entity identity and data. Check success/failure/cancellation, missing owners, competing state writers and dependency direction. Name configuration, UX, validation and production disciplines where the feature depends on them.

Inspect uncertainty where it changes the decision: world, encounter, self, rule and outcome; reveal timing, commitment already paid, available responses and retained learning. Preserve the author's chosen agency/identity rather than automatically adding selection, rerolls or reversibility.

Evaluate direct consequences and adaptation through repeated play. Read [design-research](../../policies/design-research.md) when a causal assumption can change the architecture. A prototype measures timing, perception or frequency; it cannot choose the game's intended values.

Return the recommended decomposition, exact owners/interfaces, material conflicts/gaps and affected consumers. Implement authorized architecture work under [editing](../../policies/editing.md); do not stop at an audit when edits were requested.

For topology/sector production load [spatial-design](../../references/spatial-design.md). Load another skill only for evidence that changes the current decision; there is no prescribed review chain.
