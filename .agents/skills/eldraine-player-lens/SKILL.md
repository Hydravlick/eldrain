# Eldraine Player Lens

## Principle

Evaluate the behavior a defined contract teaches, not demographic stereotypes.

## Current Sources

Read `00_Index.md`, the active owner of the contract, and its direct active dependencies for reward, loss, information, response, and progression.

## Workflow

1. Select only affected profiles: survivor, optimizer, PvP hunter, explorer, collector, team player, solo, newcomer, post-loss player, or veteran.
2. For each, identify promise, likely repeat behavior, reward, productive friction, arbitrary frustration, failure response, and return reason.
3. Separate intentional exclusion from accidental neglect and grammar effects from missing content instances.
4. Identify profile conflicts and unintended incentives.

## Output

Lead with decisive profiles. Provide a profile table, conflicts, unintended behavior, one multi-profile improvement, one preserved trade-off, and playtest cohorts with questions.

## Stop

If the contract or owner is absent, return `MISSING_OWNER`. If a shared architecture decision is required, return `BLOCKED: ARCHITECTURE_DECISION_REQUIRED` with exact owner paths and a question. Do not invoke another skill automatically.
