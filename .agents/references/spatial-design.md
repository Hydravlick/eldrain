# Spatial design playbook

Use from Design Architect for a spatial grammar, Player Experience for navigation, or GDD Editor for an approved sector. Read the selected `08_World_Generation` owner and the sector manifest template through current routes. This playbook does not establish spatial canon.

Describe the spatial promise, handcrafted frame, fixed sockets/roots, procedural kernel, immutable boundaries, route layers, landmarks and connections. Identify what players can learn across variants. Trace insertion, objective, retreat and applicable exit paths for each relevant phase; check exact lifecycle/egress owners before assuming every phase permits extraction.

For a phase change trace warning -> interpretation -> route change -> decision -> commitment -> feedback -> failure. A closure should preserve the guarantees actually promised by the owner. Check convergence/camping, unreachable rewards, alternate paths and whether a traversal verb was taught before it is required.

Separate bounded state changes, prepared module variants, authored set pieces and unproven runtime simulation. Name the production method and what must be prototyped; do not present arbitrary topology deformation as cheap authored content. Distinguish a physical sector, generation snapshot and the player's representation from their current owners.

For a narratively significant POI, connect what happened, what spatial evidence supports, what the player can infer, what remains mysterious, and what decision changes. Ordinary traversal space need not have a lore essay.

Return the readable route/phase contract, connectivity evidence, production constraints and unresolved measurements. Choose the detail the task requires; no mandatory specialist chain.
