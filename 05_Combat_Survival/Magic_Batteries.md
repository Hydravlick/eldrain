# Система: Магия и Батареи

## 1. Канон батарей

Подготовленная батарея оплачивает одно значимое применение энергии: пополнение магазина одного оружия или активацию battery-powered способности. Игрок может потратить её до опустошения магазина ради готовности сейчас, но целая батарея всё равно станет пустой ячейкой. После переноса энергии отдельные выстрелы расходуют только локальный magazine оружия.

Батареи являются наследием Предтеч. Их исходные функции — маяк Ковчега и запись локальной реальности; доступная энергия была необходимым побочным процессом, который цивилизации превратили в универсальное топливо. Боевые батареи Элдрейна — целые древние матрицы, восстановленные корпуса или осколочные производные этой технологии. Их одинаковый инвентарный габарит не означает внутренний счётчик применений.

```text
Full Battery ItemID → one atomic energy transaction → Drained Cell ItemID
```

Это тот же физический ItemID. Identity, custody, provenance и размещение сохраняются; обслуживание может явно переместить вещь по обычным физическим правилам. Энергетическая операция сама не удаляет предмет и не перемещает его в схрон. Дальнейшая экономическая судьба пустой ячейки разрешается отдельно.

### Схема жизненного цикла

```yaml
battery_contract:
  state_owner: MAGIC_BATTERIES
  runtime_owner: ItemID
  state_field: battery_state
  states: [Full, Drained]
  eligible_source_state: Full
  transactions_per_full_state: 1
  post_state: Drained
  preserves_item_id: true
  internal_charge_counter: false
  partial_state: false
  source_reservation_owner: Inventory
  transaction_fields: [source_item_id, recipient_ref, eligibility, service_requirements, commit_point, result, post_state]
  atomic_result: true
  before_commit: [source_full, recipient_unchanged]
  after_commit: [source_drained, result_applied]
```

Battery не хранит magazine. В действующем контракте нет Battery Charge, частичного разряда, Weapon/Casting Reserve или ImpulsePacket/очереди. Это superseded модели; они не являются альтернативными реализациями текущего цикла.

## 2. Source reservation и атомарность

Consumer выбирает конкретную доступную Full Battery из физического Ready Access. Источник виден владельцу до обязательства расхода. Батарея в cargo сначала проходит подготовку по [[07_Gear_Inventory/Inventory_Architecture|Inventory]], а не становится доступной от нажатия кнопки.

Action связывает исходный Battery ItemID и конкретного получателя. В объявленной service-фазе, не позднее необратимой энергетической транзакции, он получает исключительную Inventory reservation этого источника. Точная фаза зависит от процедуры; отдельный глобальный battery-lock не нужен. Reload и Q/E не могут одновременно зарезервировать один источник. Недоступный источник не подменяется другой батареей внутри уже начатой операции.

Перед commit проверяются Full state, действующая reservation этого Action, актуальная custody/revision и eligibility получателя. Один commit меняет Battery на Drained и применяет результат получателю атомарно. Повтор уже принятой транзакции возвращает её результат, не расходует другую батарею и не применяет энергию повторно. [[08_World_Generation/Persistence_Ledger|Persistence Ledger]] сохраняет это решение вместе с обоими post-states.

- До commit прерывание оставляет Full Battery и неизменённый ресурс получателя. Физическое перемещение предмета не обязано откатываться.
- После commit прерывание сохраняет Drained Cell и уже применённый результат; возврата батареи нет.
- Reservation освобождается согласно исходу и release points процедуры. Освобождение источника не очищает оставшиеся телесные claims.
- Потеря источника, смена Set или изменение условий могут сделать операцию невозможной, но не переадресуют её.

Interruption, текущий Commitment и Recovery принадлежат [[05_Combat_Survival/Combat_Three_Debts|Action contract]]. Успешный commit не допускает раздельных исходов «источник разряжен, результат отсутствует» или «результат применён, источник всё ещё Full».

## 3. Reload и получатель энергии

`reload` из [[01_Core_Vision/Input_Contract|Input Contract]] — намерение обслуживания. Оно не расходует батарею при нажатии.

```text
reload intent → one eligible recipient → bound Full Battery
→ service Action eligibility → commit
→ same Battery becomes Drained + recipient magazine becomes Capacity
```

[[05_Combat_Survival/Weapon_Ranged|Weapon Ranged]] определяет magazine тех Weapon ItemID, чьи Patterns используют magazine model. Reload допустим при любом неполном magazine: 0/8, 3/8 и 7/8 пополняются до 8/8 за одну целую Full Battery. Остаток не переносится, не возвращает энергию и не уменьшает стоимость. Полный magazine даёт FULL без транзакции и без расхода источника. Если все magazine-получатели активной Set полны, R показывает FULL. Иная недоступность (нет источника, мешают claims, нет сервисного допуска) показывает собственную причину отказа, а не ложное FULL.

```yaml
reload_contract:
  intent: reload
  active_set_recipients: eligible_incomplete_magazine_itemids
  recipient_policy: most_depleted
  comparator: prototype_bound
  tie_break: deterministic_prototype_bound
  recipient_visible: true
  recipients_per_action: 1
  source_count: 1
  source_binding: immutable
  recipient_binding: immutable
  result: recipient_magazine_to_capacity
  remainder_changes_cost: false
  full_recipient: no_transaction
  repeated_intent: re_evaluate_after_completion
  resets: []
```

В dual ranged одно R выбирает most depleted eligible ranged ItemID активной Set. Comparator и deterministic tie-break остаются prototype-bound; политика должна позволять предсказать получателя по видимому состоянию. Изменение comparator не меняет лимит одного получателя. После завершения новое R заново вычисляет цель; второй неполный ствол обычно становится следующим. Одно R не обслуживает оба оружия, случайный double-tap не должен превращаться в неясную очередь дорогих обязательств.

После начала операции source и recipient связаны с ней до исхода. Switch Set не переносит reload на другой ItemID. Если получатель уже полный или иначе стал ineligible до commit, транзакция не происходит; другой получатель требует нового намерения.

### Физическое обслуживание

Pattern/service definition объявляет manipulation, требования к рукам и телу, физическое размещение источника и пустой ячейки, commit point, Recovery и release points. Подходящее equipment может предоставить другую опубликованную процедуру; оно не создаёт невидимую третью руку. Универсального требования двух рук нет.

Если для обслуживания dual-конфигурации нужно освободить руку, [[07_Gear_Inventory/Equipment_PaperDoll|PaperDoll]] отражает действительное временное occupancy, Inventory — перемещение вещи, Action — claims. Подготовленная Set не переписывается ради каждого такого движения. Два предмета можно обслуживать последовательно с реальными физическими переходами, если процедура это допускает.

Reload сам по себе не сбрасывает Heat, technical recovery, condition, другой mechanism state или bodily Action debt. Отдельно объявленная сервисная операция может работать с таким состоянием по собственному контракту; пополнение magazine этого не подразумевает. Cooling, Aim и подготовка выстрела также не являются разрядкой батареи.

### Информация об операции

Владелец видит выбранный Weapon ItemID, его magazine, конкретную Full Battery, доступность процедуры и момент принятого расхода. В dual видны два независимых magazine. EMPTY не становится автоматическим reload, выстрелом другой руки или Switch Set.

Противник читает физическую манипуляцию, занятые руки, подготовку и оставшееся уязвимое восстановление. Он не обязан видеть точный magazine или инвентарь противника. Момент commit и возврат готовности должны иметь согласованный feedback; финальная choreography остаётся prototype-bound.

### Контур экипировки

Рунный контур доставляет энергию конкретной функции и показывает передачу, нагрузку или отказ. Покой, диагностика и видимый ремонт сами по себе не разряжают батарею. Повреждение ветви не уничтожает батарею автоматически. Активная battery-powered функция объявляет собственную транзакцию; контур не создаёт скрытую постоянную плату за ношение экипировки.

Серия оружейных действий ограничивается magazine и техническим циклом устройства. Heat, Bloom, Pulse и телесный долг сохраняют своих владельцев; Battery не выдаёт отдельный параметрический бонус каждому выстрелу и не добавляет второй Dissonance occurrence поверх одной физической вспышки.

## 4. Зарядка после экстракции

Существующее правило Хаба сохраняется: после успешного возвращения вынесенные Drained Cell автоматически заряжаются через сервис Якоря или базовую станцию. Для обычных батарей это бесплатно; редкие и перегрузочные могут требовать сервис, фракционный доступ или Рез. Потерянная батарея не восстанавливается: её нужно купить, найти или получить по контракту.

Это граница дальнейшего [[06_Economy_Loot/Resource_Cycle|обращения с предметом]], а не refund рейдового расхода. Повтор старой транзакции не использует новое Full-состояние той же вещи: revision и уже принятый результат остаются различимы. Cutover не добавляет рецепты, инфраструктуру, battery variants или новые правила повторного использования.

Отдельный Reality Charge не существует как второй боевой расходник. Полная battery-powered версия оплачивается одной Full Battery; наличие особой версии действия не вводит дополнительный предмет поверх неё.

## 5. Кантрипы

Кантрип — малая версия конкретной способности, питаемая телом вместо батареи. Наличие кантрипа определяется самой способностью, а не расой целиком. [[04_Player_Entities/Specs/Dogmat|Догмат]] гарантированно получает кантрип для каждой активной способности. У других специализаций отдельная комбинация может иметь один ситуативный кантрип или не иметь его вовсе.

Пешка не создаёт объём энергии полноценной батареи. Она использует расовый телесный проводник, чтобы воспроизвести одну фазу батарейного импульса: распознать состояние, кратко удержать его внутренним порядком и передать подготовленному фокусу.

Разные народы исторически развили разные телесные проводники:

| Раса | Телесный контур | Телеграф и семейство Шрама |
|:---|:---|:---|
| **Ёж** | давление, плотность и замыкание игл | замершая стойка, надрыв основания игл, потеря подвижности |
| **Крыса** | три точки контакта и память формы | дрожь пальцев, ложное осязание, нарушение моторики |
| **Жаба** | жидкости, соли и симбиотическая среда | сухая кожа, сбой осмоса, утрата части микрофлоры |
| **Белка** | биоэлектрический потенциал нервной системы | перегрев, аритмия, тремор и сенсорный сбой |
| **Ящерица** | тепловой и хроматофорный рисунок | охлаждение, ложный контур, нарушение теплообмена |

Это не пять готовых расовых заклинаний и не пять отдельных injury-систем. Раса определяет способ проведения, телеграф и семейство возможного постоянного Шрама; конкретная способность определяет только сокращённый эффект и наличие кантрипа. Все кантрипы одной Пешки используют общий телесный долг, поэтому смена Q/E не обнуляет риск.

Батарея покупает не абстрактные `300% силы`, а полноту и повторяемость действия: дальность, длительность, число целей, стабильность и меньший рост напряжения.

| Режим | Результат | Цена |
|:---|:---|:---|
| **Батарея** | полная безопасная версия способности | одна Full Battery → Drained Cell, Heat, cooldown, обычный Pulse |
| **Кантрип из Clear** | малая версия способности | общий статус `Strained`, обычный Recovery и читаемый Pulse |
| **Кантрип из Strained** | та же малая версия | постоянный Шрам из связанного телесного семейства и состояние `Scarred` до лечения |
| **Перегрузка из Scarred** | аварийная попытка повторить действие | `Broken`: отказ функции, потеря сознания или смерть; полный эффект не гарантирован |

Кантрип поддерживает ограниченную полезность без батареи: слабое воздействие на одну цель, короткую калибровку, малую защиту или иной сокращённый эффект конкретной комбинации. Он не повторяет батарейную мощность и не должен становиться бесплатным основным циклом.

### Двухступенчатая травма

Телесный долг имеет один общий автомат состояний:

```text
Clear
  -- кантрип --> Strained
  -- после отдыха/лечения в Хабе --> Clear

Strained
  -- сознательный кантрип --> Scarred + постоянный Scar tag

Scarred
  -- лечение в Хабе --> Clear, Scar tag остаётся
  -- дальнейшая перегрузка --> Broken
```

`Strained` и `Scarred` являются острым состоянием текущей вылазки. Шрам остаётся частью биографии и билда Пешки после лечения. Он выбирается только из семейства задействованного проводника и способности: система не уменьшает случайный несвязанный параметр другого владельца.

Шрам является flaw-тегом, который меняет конкретное решение, функцию или риск. Он может ухудшить связанную моторику, теплообмен, осмос, опору или восприятие, но не обязан быть плоским штрафом ко всему персонажу.

### Телесный Долг и Дешёвая Пешка

Кантрип является аварийным продолжением цикла, а не способом конвертировать доступное тело в бесплатную командную силу.

- батарейная версия всегда полнее, стабильнее и повторяемее;
- низкий HP не усиливает кантрип;
- `Strained` предупреждает о следующем постоянном Шраме, а `Scarred` — об угрозе `Broken`;
- все Q/E делят одно острое состояние и не позволяют обойти долг чередованием способностей;
- поле, связь или контроль от кантрипа прекращаются при потере сознания или смерти пользователя, если эффект не закреплён отдельным физическим батарейным устройством;
- кантрип не производит передаваемые батареи, лечение, предметы или иной экономический ресурс.

Доступная Пешка сохраняет оружейную летальность и может совершить переворот. Она не должна становиться выгоднее мёртвой, чем живой.

Первый кантрип обязательно надрывает тело, но не создаёт отдельный уникальный дебафф каждой способности. Повтор до лечения является осознанным обменом текущего эффекта на постоянный Шрам. Следующая перегрузка ставит под угрозу функцию и жизнь Пешки.

### Типы Энергетического Контракта

| Тип способности | Обычное применение | Роль батареи |
|:---|:---|:---|
| **Телесная** | работает от стамины, биологического ресурса или HP | не обязательна; может добавить эфирную модификацию |
| **Гибридная Догмата** | каждая активная способность имеет кантрип | даёт полную устойчивую версию |
| **Гибридная другой специализации** | конкретная способность может иметь кантрип или требовать батарею | наличие задаётся полем `cantrip_version` |
| **Технологическая** | без требуемого источника заблокирована | обязательна; кантрип отсутствует |

Таран Ежа, естественные иглы, хвост или биологический токсин не блокируются отсутствием Full Battery. Цепная молния Догмата обязана иметь кантрип; у другой специализации кантрип возможен только при прямой записи конкретной способности. Reality Burn и работа сложного устройства требуют подготовленный источник энергии, если способность явно не определяет малую телесную версию.

## 6. Выбор Источника и Управление

Выбор источника использует один моторный контракт для любой способности, у которой задан `cantrip_version`:

```text
profile_q / profile_e -> запросить обычную версию; для battery-powered версии — Full Battery transaction
cantrip_modifier + profile_q / profile_e -> явно запросить кантрип от тела
```

Bindings принадлежат [[01_Core_Vision/Input_Contract|Input Contract]]. Прежний PC-default Alt для кантрипа — superseded: в gameplay Left Alt относится только к Aim. `cantrip_modifier` сохраняет явный выбор телесной версии, но его новый default binding для PC/gamepad остаётся TBD / migration-required. Это изменение маршрутизации ввода, не переработка батарейного или cantrip gameplay cycle.

### Защита от случайной перегрузки

- Кантрип никогда не включается автоматически.
- Обычное `Q/E` при отсутствии доступной Full Battery даёт сухой отклик и не запускает кантрип автоматически.
- HUD показывает актуальное назначение `cantrip_modifier` и подходящей profile operation, если кантрип доступен; пока binding не выбран, он не подставляет старый Alt.
- Способность с `cantrip_version:: none` без источника остаётся заблокированной.
- Переназначение управления сохраняет разделение `обычное применение / сознательный кантрип`.

### HUD

Иконка способности показывает тип источника:

- `тело` — телесная способность;
- `батарея / кантрип` — способность с доступным кантрипом;
- `батарея / тело` — гибридная способность другой специализации, где тело не заменяет источник;
- `батарея` — технологическая.

Для способности с кантрипом основной режим остаётся батарейным. При удержании модификатора HUD показывает только следующий телесный переход и связанную функцию:

```text
Clear    -> Strained
Strained -> Permanent Scar: motor / osmosis / thermal / support / sensory
Scarred  -> Broken: function at risk
```

Отпускание модификатора отменяет предпросмотр; нажатие способности подтверждает переход. Heat, Pulse и Recovery остаются обычной обратной связью самого действия и не дублируются отдельной таблицей кантрипной травмы.

Цветовые состояния:

- голубой — готово от батареи;
- белый — телесная способность готова;
- янтарный — следующий кантрип создаст `Strained`;
- красный — следующий кантрип оставит постоянный Шрам;
- красный пульсирующий — дальнейшая перегрузка грозит `Broken` и смертью;
- перечеркнутый — действие невозможно без требуемого источника.

Цена также читается через тело Пешки: светящиеся сосуды, дрожь рук, болезненный вдох, треск маски и нестабильный прицел после применения.
